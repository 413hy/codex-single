## 2. 为什么不能沿用旧评测合同

旧版本把“大致止盈位”、target-first、目标/失效几何、价格漂移和宿主 ATR/噪声距离边界纳入成败，导致模型已经给出可读方向后仍整轮归零，也促使监测规则围绕目标或微观波动。用户最终确认的系统只需要模型方向；大致止盈只展示，实时监测只观察方向是否受到反向结构威胁。

当前评审项改为：

- 全部五币独立分析、恰好 Top2；
- 近 30–60 分钟方向是否基于完成 15m/5m 结构；
- 形成中 15m/30m/1h 与下一根完整 15m 是否窗口正确；
- 正式失效是否为完成 K 线结构；
- 阈值是否是尚未满足的反向结构威胁；
- 微观/OI 数据是否仅作组合确认；
- crossing 后能否独立复核并产生新规则；
- 最新 scheduled 是否能拒绝迟到 urgent 覆盖。

## 3. 针对默认模型的对齐与定制

模型不是被允许自由重写产品策略，而是通过版本化 Prompt、严格 Schema、只读工具协议和项目 Skill 理解各模块职责。

当前定制资产：

- `prompts/signal_analysis_zh.md`：定时五币、紧急单币、四窗口、仅展示止盈、方向失效与候选规则；
- `prompts/monitoring_review_zh.md`：独立阈值语义/距离复核；
- `.agents/skills/analyze-bybit-ultrashort-signals/SKILL.md`；
- `.agents/skills/analyze-bybit-ultrashort-signals/references/operating-contract.md`；
- 严格 Pydantic JSON Schema 与宿主白名单只读工具。

关键对齐：

1. 过滤分数只代表值得分析，模型必须独立决定方向。
2. 每一步都围绕模型：采集是传感器，监测是观察哨，Telegram 是展示，宿主不是第二个策略大脑。
3. SCHEDULED 必须返回五个 assessment，再固定 rank 1/2；不能只给 Top2，也不能因信心一般改成全 WATCH。
4. EMERGENCY crossing 不携带“方向已经失效”的结论；模型用新证据重新判断。
5. 监测 primary 是反向完成价格结构；OI、成交差、盘口等不能独立唤醒。
6. 阈值先由模型产生，再由同一默认模型基于新采证据审核/重写；宿主只做机械校验。
7. 每条规则必须解释与完成柱基线、pivot/range、ATR、近期 1m/5m 波动、点差和流动性的距离，避免普通几分钟噪声触发，也不能等结构完全失效才触发。
8. 连续 N 根完成柱同时写入结构字段，杜绝提示语义与执行行为不一致。
9. `hysteresis` 仅用于触发后的重新武装，不参与首次 crossing 距离；模型必须按完整 primary + consecutive + confirmations 审计实际等待。
10. 模型复核后的完成柱基线若在激活前变化，只要固定 threshold 尚未满足，宿主机械更新同一 threshold 的基线；若已穿越或规则不可执行，才只重采/重审该币，不替模型改值。

没有采用模型曾提出的“允许少于两个主信号”“微观多指标投票即可唤醒”“高周期必须同向”等建议，因为它们与已确认需求冲突。

## 5. 最终结论

默认保持 `gpt-5.6-terra / medium`。当前定制重点不是给模型加更多情绪化方向规则，而是让它清楚数据、方向、阈值、监测和版本各自负责什么，并通过独立阈值复核减少无意义唤醒。后续若真实方向误差持续出现，应按冻结的证据、时间窗口和预测结果做样本归因，再决定改 Prompt、数据还是模型；不能根据单次 FHE/ACU 等结果不断抬高门槛直至只剩 WATCH。
