# 固定双主信号实施计划

1. 扩展领域合同：周期模式、周期状态、selection rank、confidence、selected symbols/count 与新生命周期；保持旧 SQLite JSON 可读取。
2. 重写定时分析合同：正常批次必须恰好选出两个相对最优主信号，非主信号不带监测指令；紧急单币分析使用独立校验模式。
3. 调整方向策略：15m/5m 决定 30–60 分钟方向，双假设比较；宿主联合冲突校验只作用于主信号，不自动生成方向或降级 WATCH。
4. 重构周期编排与存储查询：最近成功定时周期、上一轮主信号、定时/紧急隔离、模型失败周期与向后兼容。
5. 限制实时监测：只加载最近成功定时周期的两个主信号，紧急失效可移除，历史 WATCH/退出币不残留。
6. 重做 Telegram：固定两个主卡、上轮信号更新、紧急/故障独立格式、详情与返回使用原消息编辑并提供降级路径。
7. 调整 MCP 与状态：最新主信号固定读取成功定时周期，阈值只返回当前主信号；健康状态显示模型状态和最近紧急周期。
8. 加入模型错误分类与状态去重：401/403/credits 不做同轮重复调用，不产生伪信号，只在故障/恢复变化时通知。
9. 补充单元、场景与历史回放测试，运行 pytest、Ruff、mypy、配置和安全扫描。
10. 运行真实 Bybit no-notify、FHE/TUT/HFT Codex 回放、Telegram/MCP 灰盒；提交后启动新服务并验证正式两个主信号周期与下一墙钟周期。
11. 新增完成 30m K 线采集与证据，输出形成中 15m/30m/1h 和下一根 15m 四项窗口预测。
12. 将新周期合同升级为 v3，旧 SQLite 周期保持可读；补充窗口边界、长 Telegram HTML、真实 no-notify 与预测回放验证。
