# 用户操作流程复核

## 上次遗漏原因

旧测试验证了既有UTC时间桶调度和当时误解后的底部币种菜单，没有把用户操作预期写成验收场景。全量通过不能证明交互需求理解正确。本次以实际09:17恢复/09:20重复启动日志以及用户确认的键盘分工建立回归。

## 修改

- 每条汇总内嵌币种按钮，通过signal_id固定原轮次；底部仅管理菜单，暂停/恢复单个位置。
- 点击分析频率后直接回复1—1440整数，再点击保存或取消；输入及预览持久化，10分钟超时；导航离开取消待设置状态，过期及旧按钮不能覆盖新设置；指令仅备用。
- 分析异常页提供失败通知重试按钮；分析异常通知不再展示无法执行的旧重试按钮。
- 自动调度事务原子认领周期并保存下一次启动时间，取消UTC边界重复触发。空闲恢复立即一轮，重复恢复不改计时，分析中暂停再恢复不附加一轮；保存新频率从保存时刻计时；耗时超过间隔的轮次结束后再等待完整间隔；停机不补跑多轮。
- 旧底部币种文字请求引导到最近分析，随后从通知内嵌按钮查看；旧内嵌详情按钮继续支持。

## 本轮结果

分析146、普通171、对冲193，共510项通过；三项目Ruff和mypy通过。
包含真实子进程取消、隔离跨项目发布/消费者/执行器、HMAC与HTTP灰盒、对冲多代与异常竞态既有回归。
新增使用场景：09:17恢复后09:20不执行、09:37才执行；重启及重复恢复不提前；分析中暂停/恢复；频率保存重新计时；停机不补跑；旧库迁移；超长分析；数字输入/保存/取消/过期/越权/旧按钮；HTTP层区分汇总inline_keyboard和管理reply keyboard。

本轮测试不创建在线交易、不恢复在线分析、不修改模型Prompt。Telegram手机客户端实际视觉和手指点击仍需用户观察；HTTP灰盒不冒充真实点击。
