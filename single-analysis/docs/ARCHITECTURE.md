# 三系统接口

## 本机发布

`signals.db/publications`：自增序号、唯一signal_id、symbol、published_at、expires_at和JSON payload。
JSON version=1；内容包含方向LONG/SHORT/SKIP、reason、normal_candidate、hedge（group_id、generation或null）、行情时间和60秒有效期。
每个交易系统只读打开库，按自己的signals表唯一主键`feed:<signal_id>`认领，发布者不写交易账本。
消费者不调用模型、不发分析请求。重复、过期、无方向、暂停的普通信号不执行。额外双仓信号仅匹配当前LOCKED组与轮次时管理仓位。
正常入选且是双仓币时只分析一次，normal_candidate=true与hedge字段同时存在；普通系统可按自身持仓决定是否开仓。
信号有效期同时传给开仓/重新判向执行器，下单准备超时必须跳过。已经提交的交易动作按持久意图完成恢复，不重放信号。

## 探测

嗅探程序在single-analysis内，以SQLite只读事务获取对冲系统状态。仓位快照由交易服务每5秒查询交易所更新，嗅探不复制API密钥，也不从普通系统读取仓位。
只选择已全成且撤掉退出单后进入LOCKED的对冲组；部分对冲成交不进入判向名单。
快照不新鲜或账本与仓位不一致时分析系统报错；交易监控继续运行。

## 故障隔离

分析服务故障不停止交易所TP/SL和本地仓位监控；新开仓等待有效信号。
公共模型故障同轮停止后续调用。筛选业务校验失败时仍可分析已有双仓；不二次调用同币种模型。
Bot与分析调度独立运行，消息发送失败不阻塞信号发布，最多两次自动投递后等待人工重发。
两个交易Bot只保留交易通知。已有模型异常历史保留，但迁移时明确标记已移交分析系统。

## 模型分析流程速查

默认每20分钟：嗅探已锁定双仓 → 前10候选全部采集 → 10份有效证据按小长线方向相对排序 → 普通1—3币与双仓币去重 → 双仓重点、每币一次方向判断 → 即时发布60秒信号。
方向以一周15m/30m/1h/2h量价为主，近12小时短周期行情与盘口/主动成交样本辅助。
普通首选必须输出LONG/SHORT，其余无方向等待下一轮；模型服务额度/容量异常停止本轮剩余调用；不自动改模型、不二次追问。
分析系统无交易密钥。数量、资金、杠杆、止盈可达性及订单价格由各交易系统决定。

## 至少一个方向的合同

筛选Schema版本2要求覆盖10个不同币种、选中1—3个、连续排名；选中项有明确初判方向和HIGH/MEDIUM/LOW定性置信度。首选经一周量价完整证据复核时，方向Schema只允许LONG/SHORT；其他币允许SKIP。初判不锁死最终方向，模型可以根据完整证据更正。

首选未能发布有效方向时周期标为PARTIAL_ERROR，并发PRIMARY_DIRECTION异常，不能把全无方向记作正常。缺行情或额度错误不会被程序补造方向，同币种不二次调用。普通首选恰为双仓时合并一次必判调用，额外双仓仍可SKIP等待。
