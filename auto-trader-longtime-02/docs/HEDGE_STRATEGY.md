# 对冲状态与实现边界

## 状态

`ARMING`挂止盈/对冲 → `SINGLE`顺向仓与待成交对冲 → `LOCKING`全成后撤止盈 → `LOCKED`双向等待判向。

有效方向进入`UNLOCKING`：持久化判断时的基准价与目标，先确认逆向平仓，再回到`ARMING`，先挂顺向止盈，之后挂反向开仓对冲。止盈若在对冲提交前已成交，不再提交对冲，结束该组；未提交的子仓记录记为UNFILLED。
顺向先退出进入`CLEANUP`：撤对冲、核对终态及实际累计成交、只减仓平反向余仓 → `DONE`。

所有订单意图先写SQLite；未知响应按原ID查单，不重复开仓。所有状态变更由同一交易锁串行执行。
平仓使用市价Reduce-Only；对冲开仓始终限价。未发送的对冲触发价若已经被越过，保留同价普通限价委托，不追价、不转市价。

## 价格

以Q表示当前币数量，P表示基准：看多止盈距离为P+0.5/Q，对冲为P−1.7/Q；看空镜像。
重新判向采用模型返回后获取的可执行报价（多ask、空bid）。重新判向的0.5U是相对于该报价的毛收益距离，不保证整笔最终净赚0.5U。
首次开仓TP保留原净收益计算与成本估计。价格按合约tick舍入；对冲向基准舍入，误差不超过一tick。

## 成交与通知

每5秒核对仓位/订单（原项目30秒）。计时优先使用交易所首次成交时间，接口证据未同步时使用首次观察时间。
30秒阈值受轮询和接口延迟影响，正常最多约一个轮询间隔的观察延迟。部分通知最多一次，全成通知最多一次，重启不重置。
交易所确认全部成交才取消顺向止盈；取消与成交发生竞争时重新读取仓位，不按本地预计数量平仓。

## 恢复与账本

每条方向仓位单独记账；逆向已平后无需等待历史PnL同步就能保护顺向仓。
旧仓位保持SETTLING并按自己的订单ID核账，允许新一轮在空出的方向槽位建立新仓。
未知或被外部修改的仓位/订单会停止推进并报警；不接管其他系统持仓。
明确拒绝最多两次自动提交；响应不确定只核对。取消、拒单或平仓重试预算耗尽需要人工核对，不能靠重启刷新预算。

## 验证范围

离线模拟覆盖价格镜像、等量对冲、部分成交保留TP、30秒通知合并、重启去重、止盈先发生、撤单竞争、无方向、TP不可达、双向重新判向、旧仓核账延迟、丢失应答恢复、暂停时双仓继续分析。
原项目测试保留用于基础传输、账本与Telegram回归；模型测试已迁移single-analysis。旧Executor类的SL测试不代表新App挂SL，新App使用HedgeExecutor。
2026-09-15已使用独立Demo凭据完成四轮真实交易场景验证，包括条件限价触发全成、撤TP锁仓、多空解锁、TP先成交与撤余单、交易Bot投递、重启去重和逐笔对账。测试用短距离只修改标记的测试仓，默认0.5/1.7未改。超过30秒的部分成交等仍由模拟覆盖。详见 `/root/single-analysis/docs/ACCEPTANCE.md`。
