# 对冲状态与实现边界

## 状态

`ARMING`挂止盈/对冲 → `SINGLE`顺向仓与待成交对冲 → `LOCKING`全成后撤止盈 → `LOCKED`双向等待判向。

有效方向进入`UNLOCKING`：持久化本轮判向时的报价、止盈价与对冲基准，先确认逆向平仓，再回到`ARMING`，先挂本轮新止盈，之后挂反向开仓对冲。止盈若在对冲提交前已成交，不再提交对冲，结束该组；未提交的子仓记录记为UNFILLED。
顺向先退出进入`CLEANUP`：撤对冲、核对终态及实际累计成交、只减仓平反向余仓 → `DONE`。

所有订单意图先写SQLite；未知响应按原ID查单，不重复开仓。所有状态变更由同一交易锁串行执行。
平仓使用市价Reduce-Only；对冲开仓始终限价。未发送的对冲触发价若已经被越过，保留同价普通限价委托，不追价、不转市价。

## 价格

以Q表示当前币数量、P表示重新判向时的报价、T表示该仓位持久化的TP目标、H表示该仓位持久化的对冲价格距离：看多新止盈价约为P+T/Q，新对冲价约为P−H/Q；看空镜像。程序初始默认T=0.5U、H=1.7U；人工设置和旧仓意图可以不同，均沿用各自保存的数值。
重新判向采用模型返回后获取的可执行报价（多ask、空bid）作为两张新订单的共同基准。本轮价格和订单意图持久化，监控或重启恢复只核对原订单，不重新采价或移动价格。重新判向的T是相对于本轮报价的毛收益距离，不保证原仓位或整个对冲组最终净盈利；实际成交还受费用和撮合价格影响。止盈提交后复查订单和仓位，若止盈已成交或部分成交，不提交等量的新反向开仓单。
价格按合约tick舍入；对冲向基准舍入，误差不超过一tick。

## 成交与通知

每5秒核对仓位/订单（原项目30秒）。计时优先使用交易所首次成交时间，接口证据未同步时使用首次观察时间。
30秒阈值受轮询和接口延迟影响，正常最多约一个轮询间隔的观察延迟。部分通知最多一次，全成通知最多一次，重启不重置。
交易所确认全部成交才取消顺向止盈；取消与成交发生竞争时重新读取仓位，不按本地预计数量平仓。

## 恢复与账本

每条方向仓位单独记账；逆向已平后无需等待历史PnL同步就能保护顺向仓。
旧仓位保持SETTLING并按自己的订单ID核账，允许新一轮在空出的方向槽位建立新仓。
未知或被外部修改的仓位/订单会停止推进并报警；不接管其他系统持仓。
明确拒绝最多两次自动提交；响应不确定只核对。取消、拒单或平仓重试预算耗尽需要人工核对，不能靠重启刷新预算。
