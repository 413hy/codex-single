## 修改前

- 阅读README.md、docs/OPERATING_RULES.md及所修改模块对应测试。模块来源见docs/REUSE.md，真实测试证据见docs/ACCEPTANCE.md。
- 不修改或重启其他交易项目；复用通过本项目适配层和vendor代码完成。
- 不读取输出、提交或在日志中暴露.env、Bot Token、API Secret和Codex认证文件。

## 代码边界

- 私有接口只允许Bybit Demo；不能静默改为正式盘或Testnet。
- 选币参考信号系统：前10候选采集、6份有效证据横向复核，筛选模型最多选0—3个；仅入选币进入方向模型，不凑数或递补。两层均严格Schema；资金、杠杆、数量、订单、TP/SL完全由程序决定。
- Decimal处理金额、价格、数量，按交易所精度舍入；杠杆不得超过5x，保留资金边界。
- 下单前持久化意图；响应不确定先按原ID核对，不直接重新开仓。
- 已有仓位退出策略分析。禁止增加主动平仓、反手、加减仓、移动TP/SL或持仓时间限制。
- TP/SL只能Reduce-Only，SL优先保证市价退出。失败只自动重试一次；不要用重启或后台轮询刷新预算。
- 数据库以SQLite事务保存生命周期与outbox，交易所是实时仓位和订单状态来源。
- 日志包含事件与可定位标识，正常策略SKIP不能当系统ERROR刷屏；真实错误不能靠吞异常掩盖。
- 不引入自动学习、自行调阈值或自行改Prompt。Prompt调整应保留版本证据和真实调用验证。

## 风格与验证

Python 3.11+，遵循pyproject.toml中Ruff/mypy配置。优先复用已有清晰模块，不增加不必要的框架或服务。

影响执行、状态恢复、重试、模型输出的改动，应运行相关测试及所需回归；实际接口变更需验证Demo真实边界。单纯文档改动无需重复交易或全量测试。

常用检查：`.venv/bin/ruff check src tests scripts`、`.venv/bin/mypy src`、`.venv/bin/pytest -q`。

部署前明确是否有在途订单、真实仓位和正在执行的周期；保留账本。不能删除cycle或order记录来强制重跑。使用systemd正常停止/重启；不要同时启动多个共享runtime的交易进程。
